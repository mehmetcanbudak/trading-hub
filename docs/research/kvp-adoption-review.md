## 4. Ordered safe batches for joint selection

These are **proposal batches**, not approval to implement all rows. Select individual capabilities before a new isolated branch; each batch must land and satisfy its gates independently.

1. **Chart ergonomics + source transparency:** keyboard/period command surface over our existing explicit-selection search, shortcuts/help, rectangle zoom/reset/autoscale and read-only source viewer. Copy-to-edit only with reliable mapping/renaming/dependency handling. Best incremental value with no new provider or order route.
2. **Visual planning + observed flow:** drawing-only risk/reward, on-chart anchored VWAP, bounded CPU fixed-range profile, narrowly missing profile style controls, CVD views/resets and local-only alert UX. Dependencies: contract-unit sizing and shared study provenance; retain current zoom/profile safety/performance work. Divergences require confirmation-time labels.
3. **Selected analytical extras, not VP Ultimate wholesale:** multi/prior/closing/rolling/session VWAP, yearly naked POC, session/key-level/inside-day/robust-volume features, optionally mapped Bollinger. Add only selected missing controls. Durable result caching and transformed profiles require correction-safe identities, precision and resource limits first; do not create duplicate VWAP/profile engines.
4. **Explicit demand + separate redesign reviews:** sampled book/heatmap; isolated practice replay; SMC/HTF research displays; aggregate data; optional Pine/model handoff and external alerts. Data provenance/retention comes **before** book overlays; isolated run accounting before replay results; available-at timestamps before pattern signals. Longbridge only if its markets are actually selected. Bybit live execution remains a separate highest-risk project behind our existing safety stack.

**Not in any batch:** KVP branding/storage migration, older broker/runner/bracket/ledger replacement, direct upstream automerge/release/updater-channel cutover, dense-double GPU as a mandatory dependency, or external VPFM execution. Existing user data, strategies, market files, persistent IDs, credentials, catalog architecture and safe confirmations are not migration targets.

### Release gates for any later approved adaptation

- Preserve the current English-canonical source, Spanish/Chinese catalogs, stable serialization and all ten existing attribution/license/index notices. Review additional source provenance/licenses before adding code; do not infer permission from an informal “ported from” comment.
- Run the established complete build/test/data/catalog/English gates **only after implementation is separately authorized**, plus narrowly relevant deterministic fixtures and actual isolated settings/render/input/lifecycle scenarios. Keep original failures and unsupported native/provider gates visible. Use fake providers/secrets/CLIs and temporary stores, never the personal profile.
- Prove temporal/provenance semantics with raw, compact, synthetic, corrected, missing, stale and partial-source data; repeated forming-bar updates must not double-count. Benchmark only approved candidate implementations against current bounded baselines—no fork speed claim is accepted from comments or test presence.
- Mac CPU/native input/render and resource responsiveness are separate from Windows/source builds, GPU runtime, native installer trust and real-provider entitlement. Paid/model/OAuth/demo/live-account scenarios need their own authorization. No actual-provider proof is implied by fake acceptance.

## 5. Review disposition

**Strongest recommendation:** select **batch 1**, then only the drawing/CVD portions of **batch 2** that the user wants. Evaluate VP Ultimate as a menu of incremental features rather than a product merge. Keep sampled-depth analytics and niche structure/replay/provider work behind their explicit redesign gates. **The completed non-KVP adoption already removed much of the original KVP-profile/VWAP/zoom/search gap.**

This report is the sole new repository artifact of this review. Canonical `docs/research/fork-feature-report.md`, existing execution documentation/source, production checkout, installed app, data/secret stores and Rust/Swift worktrees are unchanged by this task. Source/API inspection is complete for the selected families and reviewer handoff; **KVP acceptance remains unverified and unapproved**.
